# 第二阶段：研究与仿真契约冻结实施计划

> **供 Codex 执行：** 实施时必须使用 `superpowers:executing-plans` 和 `superpowers:test-driven-development`，逐项勾选本文件中的任务。第二阶段只创建和验证契约，不实现轨道传播、路由或队列仿真。

**目标：** 将研究问题、时间尺度、单位、Walker 星座、链路与队列、覆盖、数据划分和随机种子全部冻结成机器可验证的配置，使第三阶段无需再做建模决策。

**架构：** 使用 YAML 保存人类可读契约，Python dataclass 负责加载和交叉验证，JSON Schema 负责静态字段校验。配置是后续阶段的唯一参数来源，源码中不得复制关键常数。

**技术栈：** Python 3.9、PyYAML、标准库 `dataclasses/json/hashlib`、`unittest`。

执行第二阶段时在 `requirements.txt` 增加并锁定 `jsonschema==4.23.0`；不得自行选择其他 schema 引擎。

## 2. 必须冻结的研究契约

### 2.1 研究问题

- **RQ1：** 联合使用路由状态、缺失掩码、信息年龄和动态拓扑，能否改善不完整遥测下的链路流量预测及跨策略泛化？
- **RQ2：** 因果、延迟标签感知的预测区间能否在动态拓扑、非随机缺失和分布变化下维持接近 90% 的覆盖？
- **RQ3：** 显式使用预测区间、状态新鲜度和拥塞风险后，是否能在错误预测、突发和故障下改善尾部时延与丢包？

研究不宣称提出新的共形预测或 MAPPO 基础理论，也不外推到真实商业星座和星载硬件。

### 2.2 时间尺度

必须使用双层时间轴，禁止把 5 分钟业务采样周期直接当作链路服务步长：

| 名称 | 值 | 用途 |
|---|---:|---|
| `traffic_interval_s` | 300 | Abilene 强度更新、预测样本索引、预测时域 |
| `service_step_s` | 1 | 到达、链路服务、队列、丢包和路由动作更新 |
| `routing_step_s` | 1 | 每个活跃 `(node, commodity)` 的下一跳决策 |
| `orbit_update_s` | 10 | 卫星位置、距离和计划拓扑重算 |
| `telemetry_step_s` | 1 | 完整真值采样；后续阶段再施加缺失 |
| `prediction_refresh_s` | 300 | 冻结预测器输出刷新周期 |
| `prediction_horizons` | `[1, 3]` | 对应未来 5 分钟和 15 分钟 |

每个业务时刻包含 300 个服务步和 30 个轨道更新步。所有跨尺度聚合必须采用左闭右开区间 `[k×300,(k+1)×300)`。

### 2.3 单位

| 量 | 内部单位 |
|---|---|
| 时间 | s |
| 距离 | km |
| 速度 | km/s |
| 流量速率、容量 | Mbit/s |
| 到达量、队列、缓存、服务量 | Mbit |
| 时延 | s；报告时可转换为 ms |
| 角度配置 | degree；三角函数入口转换为 radian |
| 人口与权重 | person、无量纲比例 |

禁止混用 MB、MiB、Mbit。若输出字节量，只能用 `bytes = Mbit × 1e6 / 8` 显式换算。

## 3. 星座、地球与坐标契约

### 3.1 Walker Star 66/6/2

| 参数 | 固定值 |
|---|---:|
| 星座类型 | Walker Star |
| `total_satellites` | 66 |
| `planes` | 6 |
| `satellites_per_plane` | 11 |
| `phasing` | 2 |
| `altitude_km` | 780.0 |
| `inclination_deg` | 86.4 |
| `eccentricity` | 0.0 |
| `raan_span_deg` | 180.0 |
| `raan_spacing_deg` | 30.0 |
| `epoch_utc` | `2025-01-01T00:00:00Z` |

卫星 ID 固定为 `sat_p{plane:02d}_s{slot:02d}`。平面 `p` 的 RAAN 为 `p×30°`；平面内卫星基础相位为 `s×360/11`；相邻平面相位偏移为 `p×360×2/66`。所有角度在进入计算前规范化到 `[0,360)`。

### 3.2 地球与传播

- 地球模型：第一版使用球形地球，不使用 J2、阻力或真实 TLE；
- `earth_radius_km = 6378.137`；
- `earth_mu_km3_s2 = 398600.4418`；
- `earth_rotation_rad_s = 7.2921159e-5`；
- `light_speed_km_s = 299792.458`；
- 轨道传播：解析二体圆轨道；
- 内部轨道位置为 ECI，覆盖与地面映射前转换为 ECEF/WGS84 经纬度；
- 仿真器不得调用系统当前时间，所有时间均从固定 epoch 和整数步编号推导。

## 4. 拓扑与链路契约

### 4.1 ISL 建链

- 链路按有向边存储，但物理可见性和距离由对应无向链路共享；
- 每颗卫星固定连接同轨道平面的前后相邻卫星；平面内索引循环；
- 跨轨链路只连接相邻平面 `p↔p+1`，不连接 Walker Star 接缝 `plane 5↔plane 0`；
- 跨轨候选按 ECEF/ECI 距离最小的一一互选原则匹配，卫星 ID 用作平局决胜；
- 跨轨链路在任一端 `abs(latitude)>70°` 时关闭；
- 所有链路必须通过地球遮挡检查：卫星间线段到地心的最短距离必须严格大于 `earth_radius_km`；
- `max_isl_distance_km = 5000`，超过则链路不可用；
- 最大节点度为 4；无接缝跨链时允许度数小于 4。

### 4.2 链路属性

| 参数 | 固定值/规则 |
|---|---|
| `link_capacity_mbps` | 1000.0，所有方向相同 |
| `buffer_delay_budget_s` | 0.5 |
| `buffer_capacity_mbit` | `capacity × buffer_delay_budget = 500.0` |
| `max_wait_s` | 5.0 |
| `propagation_delay_s` | `distance_km / light_speed_km_s` |
| 每服务步服务量 | `capacity_mbps × service_step_s = 1000 Mbit` |
| 队列纪律 | FIFO 的流量体积近似；本研究不模拟逐包大小 |

队列更新顺序固定为：读取步首队列 → 汇总本步所有 commodity 到达 → 缓存溢出计丢失 → 执行链路服务 → 更新步末队列。故障边服务量为 0，且不能接收新转发动作。`utilization` 以本服务步实际发送量除以服务上限计算，范围 `[0,1]`；另保存未截断的 `offered_load`。

### 4.3 需求缩放规则

链路容量不依据测试结果改动。第四阶段仅使用训练分区和 Dijkstra 行为策略标定一个全局 `demand_scale`：

1. 在无突发、无故障、完整遥测场景运行训练段代表性子集；
2. 以活跃链路每 300 秒平均利用率的 P90 为目标统计量；
3. 使用确定性二分搜索寻找使 P90 落入 `[0.55,0.65]` 的缩放系数，目标中心为 0.60；
4. 搜索范围 `[1e-3,1e3]`，最多 30 轮，相对误差阈值 1%；
5. 标定后冻结该系数，验证、校准、测试及全部策略共用；
6. 若搜索边界仍无法进入区间，停止并返回第二阶段重新审查容量，而不是在测试集调参。

## 5. 地面覆盖与接入契约

- 地面区域输入固定为第一阶段的 980 个非零人口 5°区域中心；
- 地面视为海拔 0 km 的静止点；
- `minimum_elevation_deg = 10.0`；
- 区域可见卫星集合由球形地球视线和仰角共同决定；
- 接入卫星选择最大仰角者，平局选择字典序最小 `sat_id`；
- 当前无卫星满足最低仰角时，该区域业务进入 `access_backlog`，不得静默丢弃或映射到地平线以下卫星；
- 接入映射每 `orbit_update_s=10` 秒重算；
- 第三阶段必须报告每个区域的可见卫星数、无覆盖持续时间和切换次数。

## 6. 数据划分与防泄漏契约

第一阶段 48,096 个排序后业务时刻固定划分：

| 分区 | 半开索引范围 | 数量 |
|---|---|---:|
| train | `[0, 28857)` | 28,857 |
| validation | `[28857, 36071)` | 7,214 |
| calibration | `[36071, 40880)` | 4,809 |
| test | `[40880, 48096)` | 7,216 |

- 任何 5/15 分钟预测窗口不得跨分区；
- 标准化、容量标定和超参数选择只使用 train/validation；
- calibration 只用于离线共形初始化，不参与模型拟合；
- test 只用于冻结方案后的最终评价；
- 同一业务时刻在不同策略或缺失版本下始终属于同一分区。

## 7. 随机性契约

- 开发调试种子：`202500`，不得进入正式统计；
- 正式种子：`[202501, 202502, 202503, 202504, 202505]`；
- 使用 `numpy.random.SeedSequence` 派生子种子，禁止使用 Python `hash()`；
- 派生键顺序固定为：`master_seed, scenario_id, policy_id, module_id, replicate_id`；
- `module_id` 枚举：`demand=1, burst=2, failure=3, missing=4, behavior_policy=5, model_init=6, rl_env=7`；
- 每次运行必须把 master seed、派生键和最终 32-bit seed 写入结果 manifest；
- 同一场景的不同策略共享需求、突发和故障随机流，但行为策略随机流独立。

## 10. 失败分支

| 失败 | 处理 |
|---|---|
| 时间尺度不能整除 | 停止，不允许用浮点步号；只修改契约后重验 |
| Walker 参数不能形成 66 星 | 停止，不进入第三阶段 |
| 轨内邻接距离超过 5,000 km | 在第三阶段可行性测试中回到本阶段审查距离阈值，不静默删边 |
| 覆盖存在长时间空洞 | 第三阶段报告后回到本阶段审查最低仰角或星座假设，不在 OD 生成器中伪造覆盖 |
| 训练标定无法达到 P90 0.55–0.65 | 回到本阶段审查容量；禁止使用测试集选容量 |
| schema 与 dataclass 字段不一致 | 以 YAML 契约为源，修复 schema/加载器并重新生成 audit |
| 文档仍含待定项 | 第二阶段判定失败，不进入第三阶段 |
